# Gemma 4 with LoRA Experiment in TT-XLA

This directory contains the code for the Gemma 4 LoRA fine-tuning experiments in TT-XLA.

- Gemma 4 E2B model specification can be found [here](https://huggingface.co/google/gemma-4-E2B-it).

Original LoRA paper can be found [here](https://arxiv.org/pdf/2106.09685).

## Overview

The Gemma 4 fine-tuning experiment applies the LoRA technique to adapt the instruction-tuned
`google/gemma-4-E2B-it` checkpoint on the WizardLM-Evol-Instruct (70k) instruction-following
dataset.

Gemma 4 E2B ships as a multimodal `Gemma4ForConditionalGeneration` model. At load time the
vision and audio towers (and their embedders) are dropped so PEFT only attaches LoRA to the
text attention projections (`q_proj`, `k_proj`, `v_proj`, `o_proj`).

Because we fine-tune an `-it` (instruction-tuned) checkpoint, prompts are rendered through the
tokenizer's chat template (`prompt_format: "chat"`) so the prompt boundary tokens
(`<start_of_turn>`, `<end_of_turn>`) match what the checkpoint was post-trained with.

## Requirements

This experiment requires `transformers==5.5.4`. Earlier `transformers` releases do not export
`Gemma4ForConditionalGeneration`.

```bash
pip install -U 'transformers==5.5.4'
```

## Training

The experiment supports multi-chip configurations with 1D tensor parallelism.

### Mesh and Sharding Configuration

Mesh configurations define the parallelism strategy. `input_sharding_dim` defines which mesh
dimension to use to shard inputs, while `model_sharding_patterns` defines how model weights are
sharded.

The default YAML uses Megatron-style 1D tensor parallelism: `q_proj` is column-parallel
(`["model", null]`), `o_proj` is row-parallel (`[null, "model"]`), MLP `gate_proj` and `up_proj`
are column-parallel and `down_proj` is row-parallel. LoRA `lora_A` adapters are replicated and
`lora_B` matches its base layer.

Gemma 4 E2B uses MQA (`num_key_value_heads=1`), so `k_proj` and `v_proj` are kept replicated.

Example mesh configuration in YAML:
```yaml
mesh_shape: [1, 8]
mesh_axis_names: ["batch", "model"]
input_sharding_dim: null
model_sharding_patterns:
  - ['\.self_attn\.q_proj\.base_layer$',      ["model", null]]
  - ['\.self_attn\.q_proj\.lora_B\.default$', ["model", null]]
  - ['\.self_attn\.o_proj\.base_layer$',      [null, "model"]]
  - ['\.self_attn\.o_proj\.lora_B\.default$', [null, "model"]]
  - ['\.mlp\.gate_proj$', ["model", null]]
  - ['\.mlp\.up_proj$',   ["model", null]]
  - ['\.mlp\.down_proj$', [null, "model"]]
```

## Data

WizardLM-Evol-Instruct-70k is the 70,000-row instruction-following training set used to fine-tune
the original WizardLM family. It was generated by Evol-Instruct — iteratively rewriting
Stanford-Alpaca-style instructions into more complex variants through breadth/depth evolution
prompts. Each row has two fields: `instruction` and `output`.

Source: [Hugging Face Dataset Hub](https://huggingface.co/datasets/WizardLMTeam/WizardLM_evol_instruct_70k)

Example (truncated):
```
{
  "instruction": "Can you provide a list of healthy habits to maintain a healthy lifestyle? Please format your response as an HTML page with bullet points...",
  "output": "Here's an HTML page with bullet points for healthy habits: ..."
}
```
- instruction: The (possibly evolved) user instruction.
- output: The reference assistant response (supervised target).

## Configuration

The experiment is configured using the configuration file `lora/loudbox/gemma4_e2b_wizardlm.yaml`.
The configuration file specifies the hyperparameters for the experiment, such as the number of
epochs, the batch size, and the LoRA configuration.

Current `gemma4_e2b_wizardlm.yaml` has the recommended and tested hyperparameters for the
experiment.

| `learning_rate` | Learning rate for the optimizer. | `2e-5` |

| `gradient_accumulation_steps` | Steps to accumulate gradients before updating. | `8` |
| `num_epochs` | Total number of training epochs. | `3` |
| `ignored_index` | Token id used to ignore positions in the loss (prompt mask). | `-100` |
